# Diagnostic character and face masks: verified scope

> Archived experiment: NR and face enhancement were retired on2026-09-05. Generated screenshots, obsolete docs probes and abandoned D: workspaces were removed at the user's request. Commands below record historical verification and must not be run against the current mod; its diagnostic APIs were removed. Compact JSON/results remain. See the [retirement dossier](research/2026-09-05-dlss5-retirement-dossier.md).

- Delivered: opt-in `Renderforge.CharacterMaskDiagnostic.Capture(cameraId, expectedPrefab, absoluteDirectory, occluderMode, closeUp)` on Unity's main thread. Modes: 0 none, 1 solid temporary occluder, 2 alpha-checker temporary occluder. This creates diagnostic images only. No face regeneration, material replacement, production mask consumer, ONNX model or ContentTool dependency exists.
- The runtime-selected actor's FaceTag must match one of two observed heads: Sofia Brown / `Head - Tutorial - Female_Ready` / `276b5f5f-1d18-aa64-5aef-6298b23430d6`; Yael Gonzalez / `Head_Hispanic1_F_V01_Ready` / `b522b546-b9d3-d564-3902-d78541d04c44`. Only current non-null visual roots are traversed. Unknown variants fail closed; all authored identities and customization permissions stay untouched.
- The skin submesh excludes separate eyes, eyelashes, hair and armor renderers. **Eyebrows, lips and other features painted into the same skin material remain inside the mask.** This is visible head-skin coverage, not semantic segmentation of every facial feature. Character coverage includes the current equipment/weapon renderers.
- Every capture reselects current renderers, checks actor identity plus live-root/prefab generation before drawing/readback, rejects overlapping captures, and cancels on camera target replacement/resizing. No renderer cache survives a capture. Captures install temporary command buffers and restore camera position/rotation/FOV; original sharedMaterials arrays are checked by reference. The utility is limited to the observed roster/customization setup and DLAA-sized MSAA-1 targets.

## Depth and alpha evidence

- Runtime: Unity 2019.4.31f1, D3D12, deferred GeoscapeCamera instance 300730, reversed Z, 2560x1440. Although the DLSS color target reports zero depth bits, `SetRenderTarget(mask, BuiltinRenderTextureType.CameraTarget)` at `BeforeImageEffects` successfully attaches scene depth.
- Verified shader: loaded `Hidden/Internal-Colored`, white, `ZTest Equal`, `ZWrite 0`, back-face culling, One/Zero blending. The same geometry also renders an `Always` control. Original materials and their alpha/cutout depth remain authoritative: a flat replacement pass cannot invent visible skin through scene occluders.
- The rejected experiment with `BuiltinRenderTextureType.Depth` as depth attachment logged `CommandBuffer: built-in render texture type 3 not found while executing Renderforge diagnostic masks (SetRenderTarget depth buffer)`. Its images are invalid and are not evidence of a working mask. The shipped diagnostic exposes only the proven CameraTarget binding.
- Frozen-pose Yael test: no occluder **49,032** face pixels; solid occluder **7,833**; loaded `Unlit/Colored Cutout` with a 2x2 alpha checker and cutoff 0.5 **21,058**. Unoccluded control is exactly identical in all three captures: **110,708** pixels.
- Pixel assertions passed: binary masks contain only 0/255; solid and cutout masks have **0** pixels outside the clear mask; solid has **0** pixels missing from cutout; **13,225** skin pixels reappear through alpha holes. Camera position, rotation, FOV and frozen pose are identical. [archived result: Comparison](research/2026-09-05-dlss5-retirement-dossier.md), [pixel proof](character-mask-proof/pixel-proof.json).
- Real helmet occlusion on Sofia: 968 visible skin pixels versus 14,752 unoccluded; helmet removed through the native customization toggle, 9,855 visible pixels in the initial full-body test. Separate close-ups and full masks are preserved for both fixed and ordinary heads.
- Hair `NextOption()` during capture warmup cancelled the capture with `Visual generation changed; capture cancelled.`; a new capture used the rebuilt current hair. `PreviousOption()` restored Yael's original HairTag GUID `88ca4f5b-548b-1944-ba04-293ecf1874ed`. This exercises hair lifecycle; broader head variants are deliberately unsupported.

## NR quality gate: not achieved

- Matched DLAA close-ups: NR Off; Auto defaults `1/1/1/-1`; Auto max `2/2/2/1`. `Time.timeScale=0` froze pose; each capture used 32 render frames to warm up the close-up. Camera position/rotation/FOV were identical. Post-capture `nrAlive` was **0/1/1** respectively, with success codes `nrInit/nrCreate/nrEval=0x1`.
- [archived result: Labeled comparison](research/2026-09-05-dlss5-retirement-dossier.md). NR mainly changes tone/material response; skin becomes browner/grayer and glossier, eyebrows paler and eyes muddier. These captures do not establish substantially more realistic faces. They provide no evidence of face regeneration or temporal stability.
- `source.png` is the scene-camera image before image effects/NR; `output.png` copies the actual original Renderforge driver's FP16 `outRT` after its native evaluate event. Both use the same Unity blit into ARGB32 and RGB24 PNG readback. Output images are comparison captures with that color conversion, **not** exact desktop framebuffer screenshots. Off retains the existing projection jitter; Auto suppresses it, so subpixel raster differences remain.
- Masks exclude the separate eye/hair/armor meshes, but the current NR does not consume these masks and visibly affects those regions. No unknown private NR parameter has been invented or wired.
- Original live settings were Auto `0.99/0.89/0.82/0.26`, DLAA, FG X2, auto mask true; these were restored. Time scale restored to **1**. The helmet toggle was restored, customization closed and Sofia selected in the roster. Later `GameObject.Find` returned null for both the diagnostic object and temporary occluder.
