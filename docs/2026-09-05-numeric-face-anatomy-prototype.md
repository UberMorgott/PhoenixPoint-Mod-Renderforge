# Numerical facial anatomy experiment, 2026-09-05

> Archived experiment: NR and face enhancement were retired on2026-09-05. Generated screenshots, obsolete docs probes and abandoned D: workspaces were removed at the user's request. Commands below record historical verification and must not be run against the current mod; its diagnostic APIs were removed. Compact JSON/results remain. See the [retirement dossier](research/2026-09-05-dlss5-retirement-dossier.md).

- **Rejected as a human-quality improvement.** A single shared numerical profile changed the upper eyelids on fixed Sophia and ordinary Yael. It opened the eyes slightly, sometimes making the expression more startled. The same waxy anatomy and skin response remain; configured NR Auto did not turn this into natural face reconstruction.
- This is useful evidence that compact code can change actual facial geometry through the existing rig. It does not establish that a small generic numerical profile can replace missing art/anatomy. No production hook or new settings entry was added; no per-face images, model weights, backend or downloads are runtime dependencies. Shutdown remains cancelled.
- Review: [archived result: Sophia](research/2026-09-05-dlss5-retirement-dossier.md), [archived result: Yael](research/2026-09-05-dlss5-retirement-dossier.md), [capture/restoration evidence](numeric-face-anatomy-prototype/evidence.json).

## Grounded profile

- The proposed correctable feature was the heavy upper-lid aperture seen in the original close views. This is an experimental artistic judgment, not a claim that the authored anatomy is objectively wrong.
- Real `Eye_UpEyelid_R` and `Eye_UpEyelid_L` bones both have `#Head_Addon => Human_Head_BodyPartDef` as their immediate parent. They influence 101–125 vertices each above weight 0.05 in the tested head meshes. Eyelash and eye-shadow renderers share these bones; eyeballs use separate `Eye_Socket_R/L` bones, and hair does not reference eyelid bones. The inventory records all 12 visible renderers and their bone relationships.
- The initial read-only pivot/weighted-region calculation predicted a large unwanted depth change for a three-degree local rotation. Rotation was therefore not tried. The actual tested profile is a translation in the verified common parent space: `upperLid.localPosition = original + Vector3.up * interEyeBoneDistance * 0.025f`. Both sides use the same number; rotations, scales and all other bone transforms remain authored.
- Measured Sophia inter-eye bone distance `0.0455672`, local Y offset `0.00113918`; Yael distance `0.0447051972`, offset `0.00111762993`. No head-specific bitmap or arbitrary bone-name fallback is used. Unknown head variants/parent layouts or implausible spacing fail closed.
- Immediate `BakeMesh` before/after proved that the transform changed real skin geometry: Sophia 329 vertices changed by more than `0.000001`, maximum baked-space displacement `0.00112569809`; Yael 341 vertices, maximum `0.00121532578`. These are engine mesh-coordinate measurements, not an external physical calibration. The broad head shape, source mesh, bindposes, weights, hair and eyeball rig were preserved.

## Captures and interpretation

- Each head has original/candidate pairs at camera-relative yaw 0, 45 and 90 with NR Off, plus an original/candidate front pair with NR configured Auto. Sixteen captures total; simulation was frozen at `timeScale=0`, with 32 warmup frames and unchanged camera parameters within each pair.
- The first three contact-sheet rows use the source render. The Auto row uses the actual reconstructed output texture captured by the existing diagnostic. Runtime status after the capture run was `nrInit=0x1 nrCreate=0x1 nrEval=0x1 nrAlive=1`; the NR status string was not separately stamped into each historical capture record. Yaw is relative to the existing roster camera, not a guaranteed anatomical front/profile orientation.
- The offset remained applied through 33 camera render observations per completed capture: maximum observed position drift was exactly zero. This proves the one-shot frozen-pose experiment; it does not prove animation write ownership during ordinary gameplay. There is no per-frame correction/reapplication loop.
- The visible change did not satisfy the requested substantial improvement. No random beauty sweep, second profile, gloss combination or motion sequence followed: the frozen-pose result already failed the quality gate. Original gloss remained Sophia 1 and Yael 0.5; every material and texture was untouched.

## Restoration and bounded failure behavior

- All 16 completed captures report `maxOriginalTransformDelta=0`, `destroyedBones=0`, `meshRestored=true`, `materialsUntouched=true`, `maxAppliedPositionDrift=0`. Restoration checks the original local position, rotation components and scale of all 21 captured bones, not just the two changed bones. Mesh/material checks compare the original shared references across the 12 visible renderers.
- Explicit cancellation after applying the profile also restored the original transforms with maximum delta zero and left materials/mesh unchanged.
- Switching Sophia to Yael while the profile was active produced `Visual generation changed; capture cancelled.` The old 21 bones had been destroyed. The guard did not look up or modify the new actor's bones; the existing diagnostic released its temporary resources. `meshRestored=false` and `materialsUntouched=false` in that one destruction record correctly mean the old objects no longer exist. Its zero transform delta is not a restoration claim for destroyed objects.
- An owned companion component restores the saved transforms on teardown and on synchronous failure. It never restores by bone name into a replacement character. Runtime writes are confined to the two original live transform objects.
- Final live handoff: Sophia selected, helmet visible, `timeScale=1`, NR Auto `0.99 / 0.89 / 0.82 / 0.26`, DLAA, FG X2, ShowOverlay false; `GameObject.Find("Renderforge mask diagnostic")` returned null. No game restart, runtime deployment, game save, push or shutdown occurred.
- Ordinary hair changes were not repeated in this experiment. The shared eyelid/eyelash/eye-shadow relationships were inventoried on Yael's current hair. This proves the tested fixed and ordinary heads only, not all customization variants or tactical animation.
