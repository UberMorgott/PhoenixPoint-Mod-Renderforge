## 1.6.2 contents

- **Pixel-perfect UI no longer costs frame rate** (`390b2d2`): `Canvas.pixelPerfect` is never set any more (it made the
  native canvas re-align every element each frame: 0.5-0.6 ms/frame idle, more under UI motion — the Discord "fps drops
  during animations / Personnel camera" report). `Graphic_GetPixelAdjustedRect_Patch` / `Graphic_PixelAdjustPoint_Patch`
  (`src\PixelPerfectUi.cs`) snap with their own math (round world xy of a ScreenSpaceOverlay canvas), paid only at mesh
  rebuild. Mip pin unchanged. A/B + verification: `docs\research\pixelperfect-motion-cost-2026-09-15\` (`results.md`,
  `snap-experiments.md`, `verify.md`).
- Version bump `083a939`; smoke `da79d92`; locales `41583ea` (only the stale "Animated panels may move in whole-pixel
  steps" sentence dropped from the Pixel-perfect UI bullet in all 8 files — panels move fractionally again between rebuilds).

## Codex review (`cx -Review -Commit 390b2d2 -Deep`)

- One finding, P2, `src\PixelPerfectUi.cs:27`: a parent `RectTransform` move (ScrollRect, panel animation) changes only the
  transform and does not `SetVerticesDirty()` the children, so an already-built Image/Text lands between pixels again
  until its next rebuild. Accepted as the design tradeoff this release exists for (per-frame re-snap = the cost removed;
  the release note states "only when an element's mesh is actually rebuilt"); the mip pin, which is what removed the
  TFTV icon bleed, is per-texture and unaffected. Not shipped as a fix. Revisit only if a rest-position blur is reported
  (option: dirty children on `OnRectTransformDimensionsChange`/a cheap rescan after motion stops).
