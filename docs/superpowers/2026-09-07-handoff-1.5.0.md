## User feedback (Discord, 2026-09-07) and what we did

1. "Drop ReShade: add Brightness, Saturation, Vibrance, Exposure" → 1.6.0 sliders IN PROGRESS. Codex order/math:
   `Exposure → Levels → Brightness → Contrast → Clarity → Vibrance → Saturation → LUT`; exposure `c*=exp2(EV)` [-4,4];
   brightness as midtone gamma `pow(c, exp2(-B))` [-1,1]; contrast pivot 0.18; vibrance `lerp(luma,c,1+V*(1-sat))`;
   saturation `lerp(luma,c,S)` [0,2]; defaults = identity.
   Owner: sliders need a reset. Decision (owner + Codex): ONE "Reset image settings" button row for the group (clone of a
   native button; the game has no reset in Options) + default value in every slider tooltip. No per-slider buttons.
2. "DLSS on the Geoscape smears UI elements; dark rectangles at the sides when spinning the globe" (1920x1080, D3D11).
   Diagnosed (`docs\research\geoscape-dlss-2026-09-07\`): ~48 WorldSpace "PopUp" canvases (globe markers) render through the
   scene camera at render res; Unity UI shader writes no motion vectors → DLSS reprojects them with the globe's MVs = ghost
   trails (MV debug dump: 0 in marker regions). Edge rectangles = disocclusion without history (hypothesis, NOT captured —
   Cinemachine snaps the camera back, no programmatic rotation via PPCLI). Codex + NVIDIA guide: fix = DLSS
   **bias-current-colour mask** (`NVSDK_NGX_Parameter_DLSS_Input_Bias_Current_Color_Mask`, R8 at render res, 1 = prefer
   current frame; honoured by the 3.7 models / Preset F, 310.x models "generally do not") — render marker coverage into the
   mask. Cheap test first: constant all-0 vs all-1 mask while rotating; no difference = our DLL/preset ignores it → fall
   back to rendering markers after DLSS (pitfall: occlusion by the globe). Ask the reporter whether DLAA removes the edges.
3. Fonts/icons: answered (Pixel-perfect UI; icons at their asset ceiling, measured 3 levers = 0).
