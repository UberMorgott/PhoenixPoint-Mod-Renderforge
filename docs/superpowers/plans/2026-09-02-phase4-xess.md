# Phase 4 — Intel XeSS 3 Super Resolution on D3D12 (cross-vendor path) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Intel XeSS-SR 2.0.2 (`libxess.dll`, D3D12, cross-vendor DP4a/SM6.4 path) an upscaler the player can pick in Options → Graphics, running through the SAME exported shim ABI and the SAME Unity command-list submission that Phase 2 built for DLSS on D3D12 — so switching `Upscaler: DLSS → XeSS` changes one integer and nothing else in the managed driver.

**Architecture:** Phase 2 gave the shim a device seam (`IDevice` / `Device11` / `Device12`) and put the D3D12 work on Unity's queue via `IUnityGraphicsD3D12v5::ExecuteCommandList` + a `UnityGraphicsD3D12ResourceState[]` array. Phase 4 adds a second, orthogonal seam **inside `Device12` only**: `IUpscaler` (`native/Provider.h`). `Device12` keeps its NGX code as provider `0` and, when the active provider is `2` (XeSS), records `xessD3D12Execute` into the exact same ring command list instead of `NGX_D3D12_EVALUATE_DLSS_EXT`. The resource states XeSS demands are byte-identical to DLSS's (inputs `NON_PIXEL_SHADER_RESOURCE`, output `UNORDERED_ACCESS`), so the state array is reused verbatim. XeSS has no built-in sharpness, so the shim's own NIS/RCAS compute pass (Phase 2 Task 9) runs after `xessD3D12Execute` unchanged. `Device11` is not touched — XeSS's D3D11 backend is Intel-Arc-only and explicitly out of scope.

**Tech Stack:** C++17, MSVC (VS 2022 Build Tools), CMake ≥ 3.15, D3D12 + d3dcompiler, Intel XeSS SDK 3.0.2 (`refs/XeSS-sdk`, `libxess.dll` **2.0.2.68**), NVIDIA DLSS SDK 3.10.7, Unity 2019.4 native plugin API headers (`native/unity/`), C# `net472` / `LangVersion=latest` (`Renderforge.csproj`), PowerShell 7 (`build-native.ps1`, `deploy.ps1`), PPCLI for in-game verification.

### Requirements, deployment, resource states (dev guide `doc/xess_sr_developer_guide_english.md`)

- Requirements, lines 123-130: Windows 10/11 x64 10.0.19043/22000+, **DirectX 12 with "Other vendor GPU supporting SM 6.4 and with hardware acceleration for DP4a"**. An RTX 5070 Ti satisfies this — Turing and later have DP4a. D3D11 is "Intel Arc Graphics or later" only → out of scope, confirming the spec.
- Deployment, lines 220-230: link `lib/libxess.lib` for D3D12; ship `libxess.dll` next to the executable or on the DLL search path; **also needs `msvcp140.dll`, `vcruntime140.dll`, `vcruntime140_1.dll` (MSVC redist 14.40.33810+)**.
- Resource states, lines 448-462: D3D12 inputs `D3D12_RESOURCE_STATE_NON_PIXEL_SHADER_RESOURCE`, output `D3D12_RESOURCE_STATE_UNORDERED_ACCESS`; "XeSS-SR does not perform any memory synchronization on input and output resources. It is the application's responsibility to provide resources in specified layout." → identical to DLSS's requirement, so Phase 2's Unity state array is reused unchanged. Unlike DLSS, XeSS does **not** promise to restore the states, so we keep `expected == current` and re-declare them every frame (Decision 4).
- Descriptor heap, lines 598-603: XeSS manages its own internal heap unless `XESS_INIT_FLAG_EXTERNAL_DESCRIPTOR_HEAP` is set. **We do not set it** — no descriptor budget to manage, and the flag would force us to size a heap from `xessGetProperties`.
- Heap tier, `xess_d3d12.h:154`: "XeSS supports devices starting from `D3D12_RESOURCE_HEAP_TIER_1`". No gate needed.
- Thread safety, lines 243-245: "all calls to the XeSS-SR API must be done from the same thread where XeSS-SR was initialized." → every `xess*` call in this plan happens on Unity's render thread inside the plugin render event, including create/init (Decision 3).

**Jitter derivation.** The guide writes the shear in DirectX row-vector convention (`[2][0]`, `[2][1]`), which transposes onto Unity's column-vector `p[0,2]`, `p[1,2]`. Matching term by term against `src/DlssDriver.cs:334-335`: `+2·Jx/W` vs our `+2·jx/W` ⇒ `Jx = jx`; `−2·Jy/H` vs our `+2·jy/H` ⇒ `Jy = −jy`. `FrameParams` carries `jitterX = −jx`, `jitterY = −jy`, so XeSS wants `jitterOffsetX = −fp.jitterX`, `jitterOffsetY = +fp.jitterY`.
That derivation rests on a transpose the guide never states, and the guide itself says to settle it empirically: "try experimenting with `+1` or `-1` jitter offset scaling values to appropriately align the coordinate axis" (lines 1031-1035). So the signs ship as a calibration knob — `RENDERFORGE_XESS_JITTER_SIGN` (default `-1,1`) and `RENDERFORGE_XESS_VELOCITY_SIGN` (default `1,1`) — read once at provider init, and **Task 9 Step 4 is a mandatory static-scene A/B that confirms or corrects them**. No sign is claimed correct until that screenshot exists.

## Decisions taken in this plan (and why)

1. **A provider seam inside `Device12`, not a third `IDevice`.** The device seam answers "which graphics API"; the provider seam answers "which vendor SDK". Folding XeSS into `IDevice` would duplicate the whole ring, the fence discipline and the sharpen PSO. `IUpscaler` (`native/Provider.h`) has exactly four render-thread methods and receives the already-open command list; `Device12` keeps owning submission. `Device11` compiles and behaves identically to Phase 2.
2. **`Dlss_Status`'s out-params carry `xess_result_t` while XeSS is active.** No new status export. `XESS_RESULT_SUCCESS` is `0` and `NVSDK_NGX_Result_Success` is `1`, so `Dlss_ResultString` grows a provider-aware arm and every printf that shows those ints says which provider produced them. The one place a managed caller compares against `NGX_SUCCESS` is `DlssDriver`'s `Dlss_GetOptimal` check, so `XessProvider::GetOptimal` normalises its return to `NVSDK_NGX_Result_Success` / `NVSDK_NGX_Result_Fail` and stashes the raw code in `lastError`.
3. **XeSS is created on the render thread, without a command list.** `xessD3D12Init` takes no command list and is blocking; the guide requires every `xess*` call to come from the thread that initialised XeSS (lines 243-245). Unity's plugin render event is that thread for `Evaluate`, so `Create` is driven from `DLSS_EV_CREATE` on the same thread. The Phase 2 `Begin()/End()` pair is therefore **skipped** for the XeSS create path — recording nothing and submitting an empty list would only cost a fence slot.
4. **`expected == current` in the Unity state array, re-declared every frame.** DLSS promises to restore states; XeSS says only that it does no synchronisation (lines 461-462) and never says it changes them either. Declaring `expected == current` makes Unity transition the resources in before our list and record them as unchanged after — which is what XeSS's contract asks for. Because the declaration is per-submission, a XeSS-internal state change cannot leak across frames.
5. **Delay-load `libxess.dll`.** We link `libxess.lib`, but implicit linking would resolve the DLL at `RenderforgeNative.dll` load time from the game's exe directory — not the mod folder. `/DELAYLOAD:libxess.dll` postpones that to the first XeSS call, and `XessProvider::Init` first pins the DLL with `LoadLibraryW(<dllDir>\libxess.dll)` (the same trick `Native.Load` uses managed-side). Linking against the import lib is also the build-time proof that every function this plan names really is exported.
6. **No `xessD3D12BuildPipelines`.** It only moves kernel compilation earlier; `xessD3D12Init` does it anyway, our create already happens off the hot path (mode change / level start), and the pre-build adds a second async state to poll. Skipped — add it only if a measured init stall shows up.
7. **The sharpen pass is mandatory for XeSS, not optional.** `DlssConfig.Sharpness` defaults to 40 and XeSS exposes no sharpness of its own, so without the shim's NIS pass XeSS would look softer than DLSS at the same settings for no reason. It is the same `Sharpen(cl, output, sharpness, slot)` Phase 2 Task 9 built; only the call site is new.
8. **Machine reality: only the DP4a path is testable here.** The dev box is an RTX 5070 Ti. `xessGetIntelXeFXVersion` will return `0.0.0` and the overlay will read `DP4a`. The XMX path (Intel Arc) is **implemented and reported but cannot be verified on this hardware** — the plan states that in the docs and does not claim otherwise.

```cpp
// Provider.h - the VENDOR seam, orthogonal to Device.h's API seam.
//
// Device.h answers "which graphics API" (D3D11 / D3D12). Provider.h answers "which upscaler SDK"
// (NGX / FidelityFX / XeSS). Only Device12 consults it: providers other than DLSS_P_DLSS are D3D12-only.
// Every method except Init/GetOptimal/Shutdown runs on Unity's render thread, and XeSS additionally
// requires Create to run on that same thread (XeSS-SR dev guide, "Thread safety").
#pragma once

#include <windows.h>
#include "Device.h"

struct ID3D12Device;
struct ID3D12GraphicsCommandList;

// One upscaler backend. The caller (Device12) owns the command list, the ring and the fence; a provider
// only records into the list it is given and never submits.
struct IUpscaler
{
    int lastCreate;    // vendor-native result code of the last Create   (XeSS: xess_result_t, 0 = success)
    int lastEval;      // vendor-native result code of the last Evaluate (XeSS: xess_result_t, 0 = success)
    int lastError;     // 0 = none; otherwise the same vendor-native code, latched

    IUpscaler() : lastCreate(0), lastEval(0), lastError(0) {}
    virtual ~IUpscaler() {}

    // Render thread. `dllDir` is the mod folder; the provider pins its own runtime DLL from there.
    // Returns DLSS_OK / DLSS_ERR_PROVIDER_UNAVAILABLE / DLSS_ERR_NOT_AVAILABLE / DLSS_ERR_NEEDS_DRIVER.
    virtual int Init(ID3D12Device* device, const wchar_t* dllDir, const wchar_t* logDir) = 0;

    // Render thread. Normalised to NVSDK_NGX_Result values so the flat ABI keeps one success convention:
    // NVSDK_NGX_Result_Success (1) or NVSDK_NGX_Result_Fail. The vendor code lands in lastError.
    virtual int GetOptimal(unsigned outW, unsigned outH, int quality,
                           unsigned* renderW, unsigned* renderH,
                           unsigned* minW, unsigned* minH,
                           unsigned* maxW, unsigned* maxH) = 0;

    // Render thread. No command list: XeSS's init is a blocking CPU call (xessD3D12Init).
    virtual void Create(const CreateParams& cp) = 0;

    // Render thread. Records into `cl`, which is already open. Returns false if nothing was recorded.
    virtual bool Evaluate(const FrameParams& fp, ID3D12GraphicsCommandList* cl) = 0;

    // Render thread, GPU already idle (Device12 calls WaitIdle first).
    virtual void ReleaseFeature() = 0;
    virtual void Shutdown() = 0;
    virtual bool FeatureAlive() const = 0;

    // "name,version,path" for Dlss_ProviderVersion, e.g. "XeSS,2.0.2,DP4a". Never NULL.
    virtual const char* Version() const = 0;

    // Vendor result code -> narrow string (static buffer, not thread-safe).
    virtual const char* ResultString(int result) const = 0;
};

// The singleton XeSS provider. Never NULL; Init decides whether it can actually run.
IUpscaler* MakeXessProvider();
```

```cpp
// XessProvider.cpp - Intel XeSS-SR (libxess.dll, D3D12, cross-vendor DP4a / Intel XMX) behind IUpscaler.
//
// Contract sources, all from E:\DEV\PhoenixPoint\refs\XeSS-sdk (SDK 3.0.2, libxess.dll 2.0.2.68):
//   inc/xess/xess.h, inc/xess/xess_d3d12.h, doc/xess_sr_developer_guide_english.md
//
//  * Resource states (guide "Resource States"): inputs NON_PIXEL_SHADER_RESOURCE, output UNORDERED_ACCESS.
//    Identical to DLSS's, so Device12's Unity state array is reused unchanged. XeSS does no memory
//    synchronisation of its own - the application must hand the resources over in those states.
//  * Motion vectors (guide "Motion Vectors"): screen-space pixels, CURRENT -> PREVIOUS. That is the same
//    direction Unity's DLSS path already produces, so the managed InMVScale (-renderW, -renderH), which
//    converts Unity's UV-space (current - previous) vector to pixels, is passed straight to
//    xessSetVelocityScale. No extra sign flip.
//  * Low-res MVs (no XESS_INIT_FLAG_HIGH_RES_MV) => the depth texture is required.
//  * Colour is ARGB32/R8G8B8A8_UNORM LDR => XESS_INIT_FLAG_LDR_INPUT_COLOR, exposureScale 1.0,
//    no auto-exposure (guide "Color").
//  * Descriptor heap: internal (XESS_INIT_FLAG_EXTERNAL_DESCRIPTOR_HEAP deliberately not set).
//  * Thread safety (guide "Thread safety"): every xess* call below runs on Unity's render thread.
//  * Jitter signs are a calibration knob, not a derivation: see RENDERFORGE_XESS_JITTER_SIGN below.
#include "Provider.h"
#include "RenderforgeNative.h"

#include <d3d12.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#include "xess/xess.h"
#include "xess/xess_d3d12.h"

namespace {

// Reads "x,y" from an environment variable into two floats. Absent/malformed -> defaults kept.
// The guide's own debugging advice for both jitter and velocity is to try +1/-1 per axis
// ("Debugging Tips"), and neither sign can be settled from the headers, so they stay tunable.
void ReadSignPair(const wchar_t* name, float* x, float* y)
{
    wchar_t buf[64];
    DWORD n = GetEnvironmentVariableW(name, buf, 64);
    if (n == 0 || n >= 64) return;
    float a = 0, b = 0;
    if (swscanf_s(buf, L"%f,%f", &a, &b) == 2) { *x = a; *y = b; }
}

void XESS_CALLBACK_LOG(const char* message, xess_logging_level_t level);

struct XessProvider : IUpscaler
{
    ID3D12Device* device;
    xess_context_handle_t ctx;
    int initialised;            // xessD3D12Init has succeeded for the current CreateParams
    int contextAlive;           // xessD3D12CreateContext has succeeded
    float jitterSignX, jitterSignY;
    float velSignX, velSignY;
    float velScaleX, velScaleY; // last values handed to xessSetVelocityScale
    char version[64];           // "XeSS,2.0.2,DP4a"
    char resultBuf[64];

    XessProvider() { Zero(); }

    void Zero()
    {
        device = NULL; ctx = NULL; initialised = 0; contextAlive = 0;
        jitterSignX = -1.0f; jitterSignY = 1.0f;
        velSignX = 1.0f; velSignY = 1.0f;
        velScaleX = 0.0f; velScaleY = 0.0f;
        version[0] = 0; resultBuf[0] = 0;
        lastCreate = 0; lastEval = 0; lastError = 0;
    }

    bool FeatureAlive() const override { return initialised != 0; }
    const char* Version() const override { return version[0] ? version : "XeSS,,"; }

    // ---- quality mapping -----------------------------------------------------
    // Scale factors (guide "Fixed Input Resolution"): AA 1.0x, UQ+ 1.3x, UQ 1.5x, Q 1.7x,
    // B 2.0x, P 2.3x, UP 3.0x. Never hardcode these - xessGetOptimalInputResolution is the source.
    static xess_quality_settings_t ToXessQuality(int q)
    {
        switch (q) {
        case DLSS_Q_QUALITY:             return XESS_QUALITY_SETTING_QUALITY;
        case DLSS_Q_BALANCED:            return XESS_QUALITY_SETTING_BALANCED;
        case DLSS_Q_PERFORMANCE:         return XESS_QUALITY_SETTING_PERFORMANCE;
        case DLSS_Q_ULTRA_PERFORMANCE:   return XESS_QUALITY_SETTING_ULTRA_PERFORMANCE;
        case DLSS_Q_ULTRA_QUALITY:       return XESS_QUALITY_SETTING_ULTRA_QUALITY;
        case DLSS_Q_ULTRA_QUALITY_PLUS:  return XESS_QUALITY_SETTING_ULTRA_QUALITY_PLUS;
        default:                         return XESS_QUALITY_SETTING_AA;   // DLSS_Q_DLAA = native AA
        }
    }

    void Fail(xess_result_t r) { lastError = (int)r; }

    // ---- IUpscaler -----------------------------------------------------------

    int Init(ID3D12Device* dev, const wchar_t* dllDir, const wchar_t* logDir) override
    {
        (void)logDir;
        if (contextAlive) return DLSS_OK;
        if (!dev) return DLSS_ERR_NO_DEVICE;

        // libxess.dll is delay-loaded (/DELAYLOAD in CMakeLists.txt), so pinning it from the mod folder
        // here decides which copy every later xess* call binds to.
        if (dllDir && dllDir[0]) {
            wchar_t path[MAX_PATH];
            swprintf_s(path, L"%s\\libxess.dll", dllDir);
            if (!LoadLibraryW(path)) { lastError = (int)XESS_RESULT_ERROR_CANT_LOAD_LIBRARY; return DLSS_ERR_PROVIDER_UNAVAILABLE; }
        }

        ReadSignPair(L"RENDERFORGE_XESS_JITTER_SIGN", &jitterSignX, &jitterSignY);
        ReadSignPair(L"RENDERFORGE_XESS_VELOCITY_SIGN", &velSignX, &velSignY);

        device = dev;
        xess_result_t r = xessD3D12CreateContext(device, &ctx);
        if (r != XESS_RESULT_SUCCESS) {
            Fail(r); device = NULL; ctx = NULL;
            // xess.h:377 - CreateContext returns UNSUPPORTED_DRIVER when the driver cannot run XeSS at all.
            if (r == XESS_RESULT_ERROR_UNSUPPORTED_DEVICE) return DLSS_ERR_NOT_AVAILABLE;
            if (r == XESS_RESULT_ERROR_UNSUPPORTED_DRIVER) return DLSS_ERR_NEEDS_DRIVER;
            return DLSS_ERR_PROVIDER_UNAVAILABLE;
        }
        contextAlive = 1;
        xessSetLoggingCallback(ctx, XESS_LOGGING_LEVEL_WARNING, &XESS_CALLBACK_LOG);

        // WARNING_OLD_DRIVER (2) is advisory, not fatal (guide "Driver Verification"): latch it, keep going.
        xess_result_t drv = xessIsOptimalDriver(ctx);
        if (drv == XESS_RESULT_WARNING_OLD_DRIVER) lastError = (int)drv;

        // Execution path. xess.h:216-218: xessGetIntelXeFXVersion returns the loaded Intel XeFX library
        // version on Intel platforms and 0.0.0 everywhere else. That zero IS the cross-vendor DP4a path.
        // There is no other API that reports it - xessGetProperties returns only heap/descriptor sizes.
        xess_version_t v = {}; xessGetVersion(&v);
        xess_version_t xefx = {};
        bool xmx = (xessGetIntelXeFXVersion(ctx, &xefx) == XESS_RESULT_SUCCESS) &&
                   (xefx.major || xefx.minor || xefx.patch);
        sprintf_s(version, "XeSS,%u.%u.%u,%s",
                  (unsigned)v.major, (unsigned)v.minor, (unsigned)v.patch, xmx ? "XMX" : "DP4a");
        return DLSS_OK;
    }

    int GetOptimal(unsigned outW, unsigned outH, int quality,
                   unsigned* renderW, unsigned* renderH,
                   unsigned* minW, unsigned* minH,
                   unsigned* maxW, unsigned* maxH) override
    {
        if (!contextAlive) { lastError = (int)XESS_RESULT_ERROR_UNINITIALIZED; return NVSDK_NGX_Result_Fail; }
        xess_2d_t out = { outW, outH }, opt = {}, mn = {}, mx = {};
        xess_result_t r = xessGetOptimalInputResolution(ctx, &out, ToXessQuality(quality), &opt, &mn, &mx);
        if (r != XESS_RESULT_SUCCESS) { Fail(r); return NVSDK_NGX_Result_Fail; }
        if (renderW) *renderW = opt.x; if (renderH) *renderH = opt.y;
        if (minW) *minW = mn.x;        if (minH) *minH = mn.y;
        if (maxW) *maxW = mx.x;        if (maxH) *maxH = mx.y;
        return NVSDK_NGX_Result_Success;
    }

    void Create(const CreateParams& cp) override
    {
        if (!contextAlive) { lastCreate = (int)XESS_RESULT_ERROR_UNINITIALIZED; lastError = lastCreate; return; }
        if (!cp.outW || !cp.outH) { lastCreate = (int)XESS_RESULT_ERROR_INVALID_ARGUMENT; lastError = lastCreate; return; }

        xess_d3d12_init_params_t ip = {};
        ip.outputResolution.x = cp.outW;
        ip.outputResolution.y = cp.outH;
        ip.qualitySetting = ToXessQuality(cp.quality);
        // Low-res MVs (default) + depth; LDR colour; no auto-exposure, no responsive mask,
        // no NDC velocity, no jittered MVs, no external descriptor heap. Depth follows the
        // managed side's reversed-Z gate, exactly like DLSS_F_DEPTH_INVERTED does for NGX.
        ip.initFlags = XESS_INIT_FLAG_LDR_INPUT_COLOR;
        if (cp.ngxFlags & NVSDK_NGX_DLSS_Feature_Flags_DepthInverted) ip.initFlags |= XESS_INIT_FLAG_INVERTED_DEPTH;
        ip.creationNodeMask = 1;
        ip.visibleNodeMask = 1;

        xess_result_t r = xessD3D12Init(ctx, &ip);
        lastCreate = (int)r;
        if (r != XESS_RESULT_SUCCESS) { initialised = 0; Fail(r); return; }
        initialised = 1;

        // Jitter is already in render-resolution pixels in [-0.5, 0.5]; only the axis signs are in question,
        // and those are applied per-frame in Evaluate. Keep XeSS's own jitter scale neutral.
        xessSetJitterScale(ctx, 1.0f, 1.0f);
        xessSetExposureMultiplier(ctx, 1.0f);
        velScaleX = velScaleY = 0.0f;      // force a re-push on the next Evaluate
    }

    bool Evaluate(const FrameParams& fp, ID3D12GraphicsCommandList* cl) override
    {
        if (!initialised || !cl) { lastEval = (int)XESS_RESULT_ERROR_UNINITIALIZED; lastError = lastEval; return false; }
        if (!fp.color || !fp.output || !fp.depth || !fp.mv) {
            lastEval = (int)XESS_RESULT_ERROR_INVALID_ARGUMENT; lastError = lastEval; return false;
        }

        // Unity's MV texture is (current - previous) in UV space; the managed side already sends
        // (-renderW, -renderH), which converts it to XeSS's "current -> previous in pixels".
        float vx = velSignX * fp.mvScaleX, vy = velSignY * fp.mvScaleY;
        if (vx != velScaleX || vy != velScaleY) {
            xessSetVelocityScale(ctx, vx, vy);
            velScaleX = vx; velScaleY = vy;
        }

        xess_d3d12_execute_params_t ep = {};
        ep.pColorTexture               = (ID3D12Resource*)fp.color;
        ep.pVelocityTexture            = (ID3D12Resource*)fp.mv;
        ep.pDepthTexture               = (ID3D12Resource*)fp.depth;
        ep.pExposureScaleTexture       = NULL;
        ep.pResponsivePixelMaskTexture = NULL;
        ep.pOutputTexture              = (ID3D12Resource*)fp.output;
        ep.jitterOffsetX = jitterSignX * fp.jitterX;
        ep.jitterOffsetY = jitterSignY * fp.jitterY;
        ep.exposureScale = 1.0f;                       // LDR colour: guide says use 1.0, no auto-exposure
        ep.resetHistory  = (uint32_t)(fp.reset ? 1 : 0);
        ep.inputWidth    = fp.renderW;
        ep.inputHeight   = fp.renderH;
        // Every *Base coordinate stays (0,0): our RTs are exactly the input/output resolution.

        xess_result_t r = xessD3D12Execute(ctx, cl, &ep);
        lastEval = (int)r;
        if (r != XESS_RESULT_SUCCESS) { Fail(r); return false; }
        return true;
    }

    void ReleaseFeature() override
    {
        // XeSS has no feature handle separate from the context; re-init is how a preset/resolution change
        // is applied (guide: "The application can reinitialize XeSS-SR if there is a change in the target
        // resolution or any other initialization parameter"). Caller has already waited for the GPU.
        initialised = 0;
    }

    void Shutdown() override
    {
        if (contextAlive && ctx) xessDestroyContext(ctx);
        Zero();
    }

    const char* ResultString(int result) const override
    {
        switch ((xess_result_t)result) {
        case XESS_RESULT_WARNING_NONEXISTING_FOLDER:  return "XESS_RESULT_WARNING_NONEXISTING_FOLDER";
        case XESS_RESULT_WARNING_OLD_DRIVER:          return "XESS_RESULT_WARNING_OLD_DRIVER";
        case XESS_RESULT_SUCCESS:                     return "XESS_RESULT_SUCCESS";
        case XESS_RESULT_ERROR_UNSUPPORTED_DEVICE:    return "XESS_RESULT_ERROR_UNSUPPORTED_DEVICE";

        case XESS_RESULT_ERROR_UNINITIALIZED:         return "XESS_RESULT_ERROR_UNINITIALIZED";
        case XESS_RESULT_ERROR_INVALID_ARGUMENT:      return "XESS_RESULT_ERROR_INVALID_ARGUMENT";
        case XESS_RESULT_ERROR_DEVICE_OUT_OF_MEMORY:  return "XESS_RESULT_ERROR_DEVICE_OUT_OF_MEMORY";
        case XESS_RESULT_ERROR_DEVICE:                return "XESS_RESULT_ERROR_DEVICE";
        case XESS_RESULT_ERROR_NOT_IMPLEMENTED:       return "XESS_RESULT_ERROR_NOT_IMPLEMENTED";
        case XESS_RESULT_ERROR_INVALID_CONTEXT:       return "XESS_RESULT_ERROR_INVALID_CONTEXT";
        case XESS_RESULT_ERROR_OPERATION_IN_PROGRESS: return "XESS_RESULT_ERROR_OPERATION_IN_PROGRESS";
        case XESS_RESULT_ERROR_UNSUPPORTED:           return "XESS_RESULT_ERROR_UNSUPPORTED";
```
