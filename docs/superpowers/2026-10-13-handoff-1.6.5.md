  generation on the render thread (`503b134`).

- FG image shake growing toward the edges (DLSS-G / XeSS-FG / FSR-FG): generator inputs broke the contract - now
  Direct3D top-down rows, paired with the frame the generator holds (`e61a825`; contract `8f13fd2`).

  time (`970797e`); XeLL owns the cap with XeSS-FG (`134efc1`); one pacer while idle (`a1cb6bc`) and at every instant -
  the SDK paces only a cap it accepted (`f0add71`). Frame limit = presented fps for all three providers.
- Geoscape markers: site markers drawn after reconstruction on D3D12 too (`0e75922`); aircraft + globe markers after
  reconstruction (`a9d21b4`); overlay lights / selection quads (`c819e4d`); far-side craft pose (`a7ed11a`).
- DLSS-G stuck off under low VRAM: `eWarnOutOfVRAM` was treated as failure (`9ec4a1c`, `43d9f9c`).
- FG enable / disable / provider switch: on/off deferred to a main-thread quiescent point with the chain pinned
  (`b1af995`, `1507c95`); state follows the SDK's answer (`5c6e07a`); queued events bound to their chain generation
  (`a44ee21`); XeLL serialised and marker-complete (`304bc6d`, `eabd5e4`, `a17e5ce`, `dbe68f5`, `1c65b18`); FSR
  teardown in AMD's order (`355d7b0`); one `slDLSSGSetOptions` per Streamline frame (`9eecd63`); refused caps
  (`d4965e3`, `63e1f65`).
- Changed: Auto quality by output height: <= 1200 DLAA, <= 2160 Quality, else Balanced (was <= 1600 Quality, else
  Performance) (`98085b4`) -> 4K Auto users lose fps, gain sharpness.
- Diagnostics: present watchdog, RIP/RSP only (`355d7b0`, `5bd3356`, `2b893b8`); build stamp in both DLLs
