# Generated head albedo prototype: quality gate failed

- Actual generated UV textures were applied to Sofia Brown and Yael Gonzalez in the running Steam game. This is a generative albedo experiment, not RTX Neural Faces or a complete reconstruction pipeline. **No generated candidate is accepted for production.** No automatic feature or persistent soldier replacement was enabled.
- Sofia's generated skin adds detail but darkens the eye area; its existing geometry, normals and eye materials still read as a game character. Reducing the verified `_GlossMapScale` from `1` to `0.35` on the temporary material reduces shiny highlights, but does not meet the human-face target. [Matched calibration](face-regeneration-prototype/sofia-calibration.png).
- Yael's first candidate changes the lip pigment registration. One targeted generation retry improves the lip coverage but still fails convincing human appearance and registration fidelity; low-resolution original normals and faceted geometry remain visible. The same bounded gloss calibration provides little visible improvement. [Original / generated / calibrated / retry](face-regeneration-prototype/yael-detail.png).
- User's clarified identity policy: retain broad head shape/type; do not preserve the old waxy texture's incidental details. A future accepted identity must stay stable when hair changes. The two generated candidates are local prototypes, not an identity cache.

## Actual source and rendering contract

| Character | Mesh | Posed vertices / triangles | Active skin shader | Source albedo |
| --- | --- | --- | --- | --- |
| Sofia | `Tutorial_Head_Female` | 2960 / 5646 | `_PX_CHR/CHR_Character_shader_OLD` | 2048x2048 `RGBA_DXT1_SRGB` |
| Yael | `Head_Hispanic1_F_V01` | 2958 / 5646 | `_PX_CHR/CHR_Character_Corrupted_shader` | 512x512 `RGBA_DXT1_SRGB` |

- Source meshes are not CPU-readable. Reading their arrays returned empty arrays and game errors; that first export was rejected. The final exporter calls actual Unity 2019.4 `SkinnedMeshRenderer.BakeMesh`, checks readable UV count, and exports **posed** vertices, normals, tangents, indices and UVs. It does not export a replacement bind-pose rig or change geometry.
- Both `_MainTex` transforms are scale `[1,1]`, offset `[0,0]`. `_BumpMap` is `RG_BC5_UNorm`, 2048x2048 for Sofia and 512x512 for Yael. `_MetallicGlossMap` is `RGBA_BC7_SRGB`. Original texture dimensions/formats, material IDs, shader IDs, keywords, float/vector values and every bound texture are recorded in [evidence](face-regeneration-prototype/evidence.json).
- Texture export uses GPU blit/readback, explicit source sRGB format detection, and restores `GL.sRGBWrite` / `RenderTexture.active`. The exported PNG contains sampled channels, not a copy of compressed GPU bytes. BC5 normal channels remain encoded; no fake normals are derived from generated color. Exact custom shader metallic/gloss channel semantics have not been established from HLSL; no replacement packed map is authored.
- Reloading the original exported albedo through the identical clone path produced face-region mean absolute RGB differences of approximately Sofia `[1.055,0.906,1.017]`, Yael `[0.831,0.496,0.414]` on the 0–255 scale, with equal camera positions. This is a practical color roundtrip check, not bit-exact framebuffer equivalence. [Roundtrip results](face-regeneration-prototype/roundtrip.json).
- `_GlossMapScale=1` was read from both real materials, checked with `HasProperty`, and changed only on their clones for one calibration at `0.35`. Sofia's observed highlight change establishes that this control is active there. No unverified scattering or specular parameter was invented.
