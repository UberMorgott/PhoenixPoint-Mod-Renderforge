## Grounded correction

- Installed `UnityEngine.CoreModule.dll` exposes `ComputeShader.HasKernel(string)`. Availability checks use it, not exception-producing `FindKernel` calls. Results are cached in weak tables by shader identity, so a replacement resource is checked afresh without retaining unloaded shader assets.
- Installed `LogHistogram.Generate` requires both `KEyeHistogramClear` and `KEyeHistogram`. Existing D3D12 repairs only handled AO, LUT baking and SSR; they did not guard this path.
- Installed `AutoExposureRenderer.Render` requires `KAutoExposureAvgLuminance_fixed` on history reset and fixed adaptation; progressive adaptation additionally needs `KAutoExposureAvgLuminance_progressive`. The new postfix refines the original support result only under D3D12. Fixed adaptation remains available when only the progressive kernel is missing.
- Installed `PostProcessLayer.ShouldGenerateLogHistogram` also accepts a light-meter request. Its `Monitor.IsRequestedAndSupported` gate is refined only for `LightMeterMonitor`. Installed `RenderMonitors` checks aggregate support and then renders all requested monitors; a separate `LightMeterMonitor.Render` prefix therefore guards the consumer even when another supported monitor is requested simultaneously. Other monitor types are unchanged. Independent review identified this aggregate-dispatch edge case before deployment.
- No profile, shader resource or adaptation setting is changed by these gates. If auto exposure is unsupported, the original `RenderBuiltins` initialization retains its white exposure texture. Tone mapping, fog of war, bloom and the remaining post effects continue through their original paths. D3D11 and supported D3D12 results are unchanged.
- Patch ownership/lifecycle remains the existing Renderforge Harmony owner. The new weak caches own no Unity resource. Invalid asset exceptions are cached as unsupported rather than repeated each frame.
